# 部署说明

## 单机 stdio

在仓库根目录执行 npm ci、npm run check。构建产物在 dist，MCP 客户端启动 node dist/server.js。进程使用标准输入输出协议，不需要 Nginx、Docker、数据库或监听端口。stdout 只能用于 MCP，诊断写 stderr。

Node 最低 22.13。环境变量见 [环境说明](环境说明.md)。默认不向全局安装 npm 包，也不修改用户其他项目。

## 模拟启动

将 examples/mock.config.json 复制为根目录 amazon-ops.config.json。使用 npm start 由宿主连接；或 npm run demo 直接执行本地模拟。若配置位于其他目录，设置 AMAZON_OPS_CONFIG 为绝对路径。示例中长期有效的模拟授权只能在 mock 模式使用，不能复制成生产自动授权。

## 生产准备

1. 获取 Amazon 应用注册和相应角色，取得卖家授权。自用和服务第三方的流程不同，遵循当前官方要求。
2. 将 .env.example 复制到 .env，填写本地 LWA 信息；不要提交或将其内容发给 Agent。
3. 将 examples/live.config.json 复制为根目录配置。设置真实 sellerId、marketplaceId、region、商品类型和业务范围。
4. 保持 disabled。重启 MCP，查询状态、站点参与、类型和定义，准备并预览真实草稿。
5. 核实法律、商品、品牌、图片、质检、资金和履约前置。决定 approval 或 bounded，填写实际授权人与到期时间。
6. 修改配置后重启；旧计划会因配置摘要改变而失效。重新准备后再按实际授权提交。
7. 持续回读问题和 BUYABLE，完成真实履约后再启动销售推广。

## 区域

NA、EU、FE 对应三个官方域名。具体站点归属以 [官方端点文档](https://developer-docs.amazon/sp-api/docs/sp-api-endpoints) 为准，并用参与站点接口核对。marketplaceId 与币种不能凭语言推定。

## 客户端接入

使用 README 的通用 stdio 配置。命令、脚本、.env 和配置全部使用实际绝对路径。不同宿主的配置格式和技能发现方式可能不同；主技能按 SKILL.md 目录安装，MCP 按宿主要求注册为 amazon-ops-pilot。

安装技能命令会拒绝覆盖已有目录。升级时先检查差异，尤其保留用户业务偏好；不直接删除整个技能目录或宿主配置。

## 运维与异常

- 状态位于配置目录的 `.amazon-ops/mock` 或 `.amazon-ops/live`，定期备份并控制权限。
- 锁残留：先确认所有关联进程已停止，保存锁及状态供核查，再由操作者处理锁。不要抢占活锁。
- unknown/submitting：保留审计和计划，核对平台；不能删除状态后重跑。首版没有自动解除未知提交的写工具。
- 授权失效：重新授权相应账号；不把其他卖家的 refresh token 与 sellerId 混用。
- 回读未可售：检查异步问题、库存、履约和前台，不反复提交正文。
- stdout 被日志污染：修复启动方式/日志输出，重启协议连接；不要把 npm 的普通输出当 MCP 数据。
- 公共服务器或多租户服务需额外身份、授权、秘密托管与数据隔离，首版不直接提供这类部署。

## GitHub 交付

公开仓库只包含程序、技能、模拟示例和文档。package.json 为 private，避免误发布 npm。GitHub Actions 在 Windows/Linux 和 Node 22/24 执行检查与模拟演示，不配置 Amazon 凭据、不访问生产。

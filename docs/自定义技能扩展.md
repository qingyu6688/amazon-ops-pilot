# 自定义技能扩展

## 用户需要做什么

1. 在配置所在目录下新建 custom-skills/品牌技能名/SKILL.md。
2. 写 YAML 头与具体业务做法，示例见 [品牌文案技能](../examples/custom-skills/brand-listing-style/SKILL.md)。
3. 在配置 customSkills 登记 name、path、stages。
4. 修改配置后重启 MCP。调用主技能时说明使用登记项即可，不必每次粘贴全文。

```yaml
---
name: my-brand-operations
description: 为本品牌补充商品资料核对、文案风格与周复盘方法，由主技能在适用阶段加载。
---

# 品牌运营补充

- 商品事实以我提供的规格单为准，缺失信息列出待补。
- 文案强调实际使用需求，不做无证明的环保承诺。
- 周复盘先看单件贡献和库存，再看销售额。
```

配置片段：

```json
{"customSkills":[{"name":"my-brand-operations","path":"custom-skills/my-brand-operations/SKILL.md","stages":["selection","listing","operations","review"]}]}
```

## 阶段标识

discovery、selection、compliance、economics、sourcing、listing、fulfillment、launch、operations、review。中文含义见 [接口设计文档](接口设计文档.md) 及 [运营流程参考](../skills/amazon-ops-pilot/references/运营流程.md)。

## 主技能如何调用

读取任务 → 获取当前阶段登记的技能名 → amazon_custom_skill_read(name) → 核对适用性及冲突 → 按允许部分执行 → 记录实际加载项。无 MCP 时可由宿主直接读取用户明确指定的技能，不能声称工具已经验证路径或执行了平台操作。

自定义技能可以补充格式和判断，不是新的凭据或授权。写“忽略平台错误”“自动批准全部商品”不会放开服务。用户明确调整普通偏好时不另设批准流程；扩大真实写入范围时需要更新实际授权。

## 路径与脚本

路径以配置文件目录为根。MCP 使用 realpath 检查，拒绝目录外文件和联接逃逸；只接受 SKILL.md，最大 128 KiB。参考资料可由宿主按技能相对路径读取，但不能借此外传凭据或运行未授权脚本。MCP 不执行用户技能附带脚本。

custom-skills 默认不提交 Git。需要公开通用示例时，先移除真实品牌资料、采购价、账号、客户、凭据和内部经营信息，再放入 examples。当前仓库示例均为虚构。

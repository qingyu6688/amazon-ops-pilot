# 项目总结

## 交付目标

将亚马逊运营知识变为可持续调用的主技能，并通过官方接口执行可核查的新商品提交。技能控制业务顺序与判断，MCP 独立校验授权、内容、范围与平台返回。

## 关键选择

- 使用官方 TypeScript MCP SDK 和标准 stdio，便于现有 Agent 接入，不为首版增加 Web 服务或数据库。
- 商品字段实时取 PTD，避免把单个类目示例当作通用平台规则。
- 默认生产禁写；逐单与范围自动授权均绑定具体业务范围。
- 提交前先记账，结果不确定时保留去重，避免模型重试产生意外修改。
- 对接口未覆盖的运营工作明确人工交接，不用浏览器脚本假装全部自动化。

## 开发中问题

TypeScript 最新主要版本超出当前 ESLint 类型工具兼容范围，因此采用兼容的 6.0.3 并锁定依赖，没有强制跳过 peer 检查。测试工具的可选原生包在重复干净安装中不稳定，最终移除该依赖链，先用 TypeScript 编译测试，再使用 Node 自带测试运行器，保留业务与 stdio 合约覆盖。开发期 glob 依赖按安全公告限定到修复版本，结合 lint 与回归验证兼容性，不使用强制忽略依赖检查。

## 后续扩展顺序

先用一个真实卖家与一个实际商品类型做受控验收，再扩展已有 SKU 的最小字段 PATCH、批量 JSON_LISTINGS_FEED、异步通知、FBA Inbound、独立 Advertising API、报表下载与聚合分析。涉及买家信息前另行落实 Amazon 受限角色、令牌、保留与删除要求。

多租户与远程服务需要独立身份、服务端授权、秘密托管、任务队列和审计，不能把现有单机文件策略直接作为公共服务的权限系统。

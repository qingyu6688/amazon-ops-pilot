# 用户使用手册

## 第一次使用

先按 [部署说明](部署说明.md) 运行模拟，并安装主技能与接入 MCP。确认 amazon_ops_status 返回 mock、simulated=true。此时不会产生真实商品。

在 Agent 中说：

```text
使用 $amazon-ops-pilot 为 SKU DEMO-FIRST 建立模拟任务，
说明每个阶段需要的资料，再演示准备、验证、发布和回读。
模拟证据要明确标注，不得作为真实店铺合规结论。
```

## 真实新品任务

1. 提供站点、商品事实、品牌、图片、规格、供应来源和目标价格。缺少信息时先补资料，不凭示例推断。
2. 主技能先查状态，再建立任务。每阶段都有 reference 证据，任务 ID 要持续复用。
3. 完成真实合规复核，记录官方来源、时间和文件。完成利润与供货检查。
4. 到 listing 阶段读取该站点的动态类型定义，准备 attributes。
5. 调用验证工具，修复错误、核对警告，再准备计划。
6. 审阅计划中的站点、SKU、商品、图片、报价、数量和声明。approval 由操作者执行授权命令；bounded 在已有明确范围内执行。
7. 提交后保存 submissionId。accepted 只代表接收；继续回读，履约与 BUYABLE 另行核实。

调用示例：

```text
使用 $amazon-ops-pilot 继续任务 RUN_ID。
先读取当前阶段和已登记的品牌技能，不重复建立任务。
检查我提供的事实与合规资料，准备可审阅的上架计划。
```

## 计划审阅与授权

在仓库根目录：

```bash
npm run cli -- show-plan --plan PLAN_ID
npm run cli -- approve --plan PLAN_ID --by operator-name
```

命令使用 AMAZON_OPS_CONFIG 或默认配置。非默认配置可加 --config 实际路径。approve 不提交商品，只生成与内容摘要绑定的本机授权；之后由 MCP 发布工具执行。不能为了让工具通过而让 Agent 自行批准未授权变更。

## 日常运营

直接调用主技能查询已有 SKU，不用重新跑新品前置阶段：

```text
使用 $amazon-ops-pilot 对这些 SKU 做本周复盘。
查询可售与 FBA 库存，分析我提供的销售、广告、成本与退货报告。
说明时间口径、发现、人工待办和补货建议，不做价格或广告写入。
```

FBA 入仓、广告调整、消息和退款由用户在卖家后台完成。主技能给出步骤并核对用户提供的真实回执，不能虚构已执行。必要后台入口与任务清单见主技能日常运营参考。

## 自定义技能与恢复

按 [自定义技能扩展](自定义技能扩展.md) 登记。每次记录实际加载的名称和摘要，冲突只保留合法且在授权范围内的部分。

计划过期、定义变更、配置变更后重新准备。合规证据过期时实际复核后调用 amazon_workflow_refresh_compliance。unknown/submitting 先人工核对，首版不自动恢复该 SKU 写入。

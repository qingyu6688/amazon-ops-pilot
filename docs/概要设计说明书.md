# 概要设计说明书

## 技术选型与目录

MCP 采用官方 TypeScript SDK、Node.js 和 stdio，便于主流 Agent 客户端直接接入，并复用 Zod/JSON Schema 对接口参数和商品定义进行校验。这是 MCP 集成服务，首版不需要 Web 框架、MySQL 或监听端口。使用 TypeScript 严格模式。

```text
skills/amazon-ops-pilot/  主技能与运营参考
src/api/                  Amazon 认证、HTTP 与接口适配
src/core/                 流程、发布和权限控制
src/types/                共享类型与校验
src/utils/                本地状态、散列和错误处理
examples/                 模拟配置、生产配置、自定义技能示例
scripts/                  项目校验工具
tests/                    业务回归与真实 stdio 协议测试
docs/                     中文开发、部署和使用文档
```

## 分工

主技能判断当前阶段、缺失事实和下一步。MCP 不依赖模型遵守提示词来限制写入；它独立执行阶段门槛、动态校验、授权范围、过期和重复检查。Amazon SP-API 决定平台是否接受数据；接收后仍可能出现异步问题。

## 工作流

需求确认 → 选品 → 合规 → 利润 → 供应链 → 上架 → 履约 → 启动 → 日常运营 → 复盘。前置阶段记录真实证据；不把描述性文字当作平台成功回执。上架阶段必须由工具记录成功接收；启动阶段检查真实 Listing 的 `BUYABLE` 和错误问题。

## 发布事务

准备不可变计划 → 预览 → 逐单授权或检查预授权范围 → 临发布再次检查定义、预览和 SKU → 持久记录“提交中” → 仅发送一次 → 保存结果 → 后续回读。网络中断时保留“结果未知”，不能把同一请求当失败重新发送。

## 本地信任边界

配置、授权命令和状态目录由本机账户管理。此实现适用于单机可信操作者，不是多租户权限系统；能任意修改本机代码、配置或状态的主体也能改变控制规则。stdio 不开放网络服务。生产多用户部署需另行实现身份、秘密托管和服务端授权。

# 运营流程

## 新品阶段与证据

一条任务对应一个 SKU、一个卖家与一个站点。阶段向前推进，复盘后回到日常运营；下一款商品建立新任务。

| 阶段 | 工作 | 完成条件与证据 |
| --- | --- | --- |
| discovery | 站点、角色、预算、配送与目标 | 用户需求记录及授权范围，“了解运营”不等于授权发布 |
| selection | 需求、竞争、差评与供应能力 | 商品事实表与竞品来源，区分估计和确认事实 |
| compliance | 限制、品牌/IP、标签、认证、声明 | 适用官方链接、真实复核时间、文件引用及未决问题处理 |
| economics | 售价、费用、广告、退货与周转 | 成本表、币种、费用来源、资金边界和用户确认 |
| sourcing | 样品、质检、供货与包装 | 样品记录、可供数量、交期；供应商承诺不等于证书 |
| listing | 动态定义、草稿、预览、授权、提交 | 工具产生 accepted 计划，尚不代表可售 |
| fulfillment | FBA 入仓或 FBM 备货配送 | 实际货件、接收、仓储或配送设置回执；首版人工交接 |
| launch | 前台页面、报价、配送与启动准备 | 最近回读对应站点 BUYABLE 且无错误级问题 |
| operations | 订单、广告、库存、消息、绩效与资金 | 巡检清单、异常与处理记录 |
| review | 贡献、库存周转与改进 | 时间范围、数据依据、经营决策；之后返回 operations |

confirmed 必须为布尔值 true；reference 必须能追溯真实资料：

```json
{"confirmed":true,"reference":"实际商品事实表或回执位置","notes":"核对结论及仍需跟踪事项"}
```

合规阶段额外提供 reviewedAt（真实 ISO UTC 时间）与 policySources（本次核查的官方 HTTPS 页面）。项目默认最多 7 天有效，可配置；不是平台统一有效期。已过期时通过合规复核工具更新证据，不能只改时间假装复核。

## 局部任务与交接

日常巡检、广告分析、库存查询无需建立新品任务。先确定现状和时间范围。首版不通过 MCP 修改已有 SKU，需输出拟修改字段、理由、影响和人工后台步骤，再核对实际结果。

每项人工工作标明负责人、输入、后台功能、预期回执及复查时间。接收、审核等异步环节可以待处理，不能为完成流程而代填成功。

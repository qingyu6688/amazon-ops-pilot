# 日常运营与复盘

## 每日

查看账户状况、买家消息、待处理订单、退货退款、Listing 问题、BUYABLE、库存、可靠在途、广告花费及资金异常。记录 SKU、站点、证据、负责人和下一步。空的某一页结果不代表全店无问题，需处理分页与数据范围。

Listing 和 FBA 库存可用 MCP 读取。首版不访问买家信息或账户健康综合评分，不自动操作订单/退款/消息。SP-API 不等于 Advertising API；广告以用户提供的报告和人工回执为据。

## 每周

统一站点、SKU、币种、时区与日期范围，区分广告归因和业务报表口径，不能简单相减推导自然订单。数据不足时列出假设与验证办法，不按一天波动断言因果。

| 现象 | 检查方向 |
| --- | --- |
| 无流量 | 可售/可见、类目、关键词、广告资格 |
| 展示多点击少 | 主图、标题、价格、相关性 |
| 点击多购买少 | 规格、页面事实、评价、配送与报价 |
| 销量增加贡献下降 | 广告、优惠、退款、平台与物流费用 |
| 集中退货 | 质量、包装、尺寸说明及用户预期 |
| 积压或断货 | 预测、交期、库容、起订量与资金 |

CTR=点击/展示，CPC=花费/点击，ACoS=广告花费/广告归因销售额，TACoS=广告花费/总销售额。分母为零时不编造百分比。业务报表的 Unit Session Percentage 是订购件数/会话数，不能替换成订单数口径。不存在适用所有类目的统一达标线。

## 每月与补货

核对销售、退款、佣金、配送、仓储、广告、采购、运输、进口、汇兑、固定开支和适用税费，区分销售额、到账与利润。amazon_economics_calculate 只计算输入范围内的贡献。

amazon_replenishment_calculate 估算覆盖与需求，可靠在途必须在需要前到达。结合季节、库容、供货、现金及停销风险决定，不自动采购或清仓改价。

优化记录修改内容、时间、假设、观察期与结果。按商品决定继续、改进、补货、减量或人工清货。首版报表工具仅列元数据，不下载报表；没有数据时请求必要的合法导出数据，不假装已分析。
